# PLAYBOOK.md — native Cursor Plan Mode artifact

`final/PLAYBOOK.md` is **not** generated by a Python template.

It is a **real Cursor Plan Mode** `.plan.md` that Spec Planner **imports** into the package via the **`playbook-importer` subagent**.

## Constructive improvement (do not remove depth)

We are **improving presentation only** — not deleting prior playbook content.

| Keep (as before) | Improve |
|------------------|---------|
| Every implementation **STEP** from `planning/implementation-plan.yaml` | Shape as native Cursor Plan **todos** + markdown body |
| Letter-to-letter pins (files, exact snippets, commands, verify) | Embed them in plan prose the way a good Cursor plan does |
| Decisions, constraints, coverage / residual scope | Situation-shaped H2s (only sections this job needs) |
| iDAG linkage (`playbook_ref` / STEP ids) | Todos and body still name STEP ids |

**Forbidden:** thinning STEPs, dropping todos that map to STEPs, or “format cleanup” that leaves the coding agent to invent.

Machine STEPs remain SoT in `planning/implementation-plan.yaml`. PLAYBOOK must still be rich enough that a coding agent can execute **without rediscovering** those STEPs.

## Mandatory generation flow

```
Agent Mode (research → decisions → STEPs / iDAG / critic …)
        │
        ▼
SwitchMode → Plan
        │
        ▼
Cursor Plan Mode creates the plan
        │   todos ≈ STEPs (same work, Cursor plan shape)
        │   body carries prior depth (pins, verify, files…)
        │   → ~/.cursor/plans/<name>_<id>.plan.md
        ▼
SwitchMode → Agent
        │
        ▼
INVOKE subagent: playbook-importer   ← mandatory (do not skip)
        │   → copy → final/PLAYBOOK.md + PLAYBOOK.import.json
        │   → validate-playbook.py
        ▼
Quality Gate / check-handoff
```

### Why the subagent

Leaving Agent Mode for Plan Mode breaks the continuous Agent loop. When you return, **`playbook-importer` must run immediately** so the native plan is copied into `final/`. Skipping it leaves a broken package.

### Rules

1. **Switch to Plan Mode** before authoring the playbook outcome.
2. **Let Cursor create the plan** — native todos + adaptive body.  
   - Frontmatter `todos`: one todo per residual STEP (or clear 1:N grouping with STEP ids in `content`).  
   - Body: include the same depth as before (exact files, final artifacts, verify, do-not) — situation-shaped sections, not a rigid dump template.
3. **Switch back to Agent Mode**.
4. **Invoke `playbook-importer`** (copies into `final/PLAYBOOK.md`). Light adjust only; never strip STEP detail.
5. YAML STEPs + iDAG stay in `planning/`; PLAYBOOK = Cursor plan for the coding agent.

## Import helper (used by playbook-importer)

```bash
python scripts/import-cursor-plan.py \
  --workspace workspace/<task-id> \
  --plan "%USERPROFILE%\.cursor\plans\<name>_<id>.plan.md"
```

Also writes `final/PLAYBOOK.import.json` — required by `validate-playbook`.

## What “good” looks like

- YAML frontmatter: `name`, `overview`, `todos` (`id`, `content`, `status`), `isProject`
- Todos cover the same work as STEPs (STEP ids visible in todo content or body)
- Body: situation-shaped H2s **as needed** — Decisions / Constraint / Concrete change / Files / Verify / Out of scope, etc.
- Letter-to-letter pins still present in the plan body where the job needs them
- **No thinner** than the prior STEP package for the same Spec
- Source / command pins in the body use the **placeholder below** — never a loose dump

## How pins appear in PLAYBOOK.md / HANDOFF.md

Fill this placeholder. Do not invent a looser layout. `<lang>` is the language discovered in the target repo (`tsx`, `python`, `bash`, `css`, `yaml`, …).

exact_snippet (`<path>`):

~~~<lang>
<complete final source — 0 or 2 spaces of indent; never start a line with 4 spaces>
~~~

exact_companion (`<path>`):

~~~<lang>
<complete final companion text>
~~~

exact_commands:

~~~bash
<proven command>
~~~

Exact copy: `<string>`.
Exact aria: `<template>`.

**Why:** PLAYBOOK/HANDOFF are GitHub-flavored markdown. A line that starts with 4 spaces is a nested code block and **splits** a `~~~` fence (first lines in a card, the rest as paragraphs). RHM’s assist wire is one ```json``` block, so outcome files must not contain ``` fences.

**Forbidden in those two files**

- Raw markup or attributes as paragraphs (`<a>`, `className=`, `aria-label=`)
- A `~~~` opener with no language
- `~~~text` around Exact copy / Exact aria (those stay one prose line)
- 4-space indented source inside or outside a fence
- Attributes or continuations on their own lines (put them on the same line as the token)

## Forbidden

- Skipping `playbook-importer` after Plan → Agent
- Removing STEPs / todos / pins “because Plan Mode is adaptive”
- `render-playbook.py` inventing a YAML-dump body
- Forcing a mechanical skeleton (`Todo -> Step map`, `**Todo id:**` dumps) *instead of* rich Cursor-plan prose that still carries the steps
- Hardcoding product-specific “things needed” into the format doc
- Loose (unfenced / 4-space) source in PLAYBOOK.md or HANDOFF.md

## Validation

`scripts/validate-playbook.py` checks Cursor-shaped frontmatter + non-thin body + anti-template dumps + import meta. Depth SoT for STEPs remains `validate-execution-depth` on YAML.
